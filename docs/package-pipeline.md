# Package pipeline (v0.24–0.27 foundation)

Optional local inbox worker: set INKVEIL_PACKAGE_INBOX to a trusted local directory and INKVEIL_IMPORT_PERMISSION=yes only when authorized. Enable a local-package source in sources.local.json with matching permission reference. Place completed ZIP packages into inbox/<source-id>/ using atomic rename from a temporary non-ZIP file. Only trusted operators may write the inbox. Worker scans every minute, imports sequentially under catalog lock, and retries failed jobs up to three times per server process. ZIP fingerprint prevents repeated processing in that process. Jobs are in memory (1000 distinct jobs per process); on restart existing packages are reconsidered, existing chapters skipped by catalog merge. Remove/archive completed packages manually. Do not run separate import CLI while server is running. No remote acquisition. Existing manifest sync remains separate.

Set INKVEIL_OPTIMIZE_IMAGES=yes to optionally recompress JPEG (quality 85) and PNG, keeping only smaller output and original dimensions. GIF and WebP unchanged; JPEG metadata may be removed. 40 megapixel bound for decoded JPEG/PNG. Back up originals. View /admin/imports for local job counts and status, or ?format=json. This is not a durable queue, external endpoint health checker or full image conversion pipeline. Tests added; run go test ./... before use.
